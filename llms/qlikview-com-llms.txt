# Qlik Help

Official product documentation for Qlik's portfolio of analytics, data integration, and data quality products — covering both cloud and client-managed deployments.

## Site
- Name: Qlik Help
- Primary URL: https://help.qlik.com/
- Type: Official product documentation (versioned)
- Two top-level product categories:
  1) Cloud
  2) Client-managed (on-prem)

## URL patterns
- Cloud product docs typically follow without a version: https://help.qlik.com/en-US/cloud-services/
- Client-managed products are versioned and follow: https://help.qlik.com/en-US/<product>/<version>/
- All URLs default to `/en-US/`. For other locales, replace `en-US` with the appropriate locale code. If the user does not specify a locale, always default to `/en-US/`. Possible locales are `de-DE`, `en-US`, `es-ES`, `fr-FR`, `it-IT`, `ja-JP`, `ko-KR`, `nl-NL`, `pl-PL`, `pt-BR`, `ru-RU`, `sv-SE`, `tr-TR`, `zh-CN` and `zh-TW`. Note that not all pages are available in all languages.

## Audience
- Admins / operators (tenant, security, deployment, governance)
- Developers / engineers (app building, scripting, APIs, connectors, pipelines)
- Data/BI users (analysis, authoring, sharing)
- Architects / security teams (identity, access, compliance, networking)

## Out of scope

This site does not provide:
- Commercial pricing or contract details
- Roadmap / future feature commitments
- Support case-specific troubleshooting beyond published documentation
- Legal interpretations of licensing terms
- Do not confuse Qlik Sense (client-managed) with Qlik Cloud (SaaS).
- Do not conflate Talend Studio with Talend Cloud — they are separate products with separate docs.
- QlikView is a legacy product; do not recommend it for new deployments.

Direct users to official sales, support, or legal channels when appropriate.

## Content freshness

- Cloud documentation reflects continuous delivery and may update without versioned URLs.
- Client-managed documentation is version-bound and must match the user’s installed release.
- When unsure, prefer the latest published Cloud documentation unless the user specifies otherwise.

## Versioning & deployment model rules (critical)
When answering questions, always determine:
1) Which category: Cloud vs Client-managed
2) Which product (from the taxonomy above)
3) Which version/release (if applicable)

Guidance:
- Client-managed documentation is often tightly versioned; prefer the exact version requested by the user.
- If the user does not specify a version, state assumptions and/or ask a clarifying question.

## Recommended interpretation for ambiguous product names
- "Qlik" alone may refer to Qlik Cloud or Qlik Sense (client-managed); confirm which.
- "Talend" may refer to Talend Cloud or one of the client-managed Talend products; confirm which.
- "Catalog" could refer to Qlik Catalog or Talend Data Catalog; confirm which.

## What to cite (preferred sources within help.qlik.com)
When grounding answers, prefer:
- Official product landing pages (to confirm scope and version)
- Concept/architecture pages (definitions and intended behavior)
- Task/procedure pages (step-by-step instructions)
- Reference pages (exact property names, defaults, constraints, supported versions)
- Troubleshooting/limits pages (known issues, error interpretation)

## Answering playbook (how an assistant should use this site)
1) Ask/confirm: Cloud vs Client-managed + product + version.
2) Start with an overview/concepts page to define terms and scope.
3) Use task pages for procedures; include prerequisites and required roles/permissions.
4) Use reference pages for exact field/property names and valid values.
5) If behavior differs by version, explicitly call out differences and link to the relevant version docs.
6) Always link to the exact version-specific page when applicable.
7) Do not link to search results.
8) Prefer deep links over landing pages when answering procedures.

## How content is typically organized (within each product)
Most products are structured into some combination of:
- Overview / Concepts (definitions, capabilities, architecture)
- Getting started (quickstarts, onboarding, first-run tasks)
- Tutorials / How-to (task-based procedures)
- Administration / Operations (configuration, monitoring, scaling, backups)
- Security / Governance (identity, permissions, auditing, compliance)
- Deployment / Installation / Upgrade (especially client-managed)
- Integration / APIs / Connectors (connectivity, authentication, limits)
- Reference (properties, dialogs, fields, settings, commands, functions)
- Troubleshooting (errors, logs, FAQs, known limitations)

## Output expectations (assistant behavior)
- Be explicit about which product and deployment model the answer applies to.
- Keep steps concise; link to authoritative pages for detail.
- If unsure due to missing version/context, ask a clarifying question rather than guessing.

## Examples
- Q: What is the largest app size supported?
  A: The largest app size supported is 50 GB (in-memory). This maximum size applies to large apps in Qlik Cloud environments. However, it's important to note that the actual supported app size can vary depending on the subscription level and the assigned large app capacity. For standard apps, the supported sizes are smaller: up to 5 GB for Qlik Sense Enterprise SaaS, up to 10 GB for Qlik Cloud Analytics Premium, and up to 15 GB for Qlik Cloud Analytics Enterprise. The large app support feature is designed to accommodate apps that exceed these standard size limits, allowing users to work with larger datasets efficiently. For the most accurate and up-to-date information on app size limits, please refer to the official Qlik Cloud documentation: [https://help.qlik.com/en-US/cloud-services/Subsystems/Hub/Content/Sense_Hub/Admin/large-app-support.htm].
- Q: How do you subscribe to a sheet?
  A: To subscribe to a sheet, you have two options: Right-click on a visualization within the sheet and select "Subscribe" from the context menu. Click on the top bar of the application and select "Subscribe to sheet" from the dropdown menu. After choosing one of these methods, you'll need to configure your subscription: Enter a title for the subscription, which will be used as the email subject. Optionally, add a description that will appear in the body of the email. Choose the format for your report: PDF or Microsoft PowerPoint. Configure the data used by the subscription, including handling variables with bookmark capabilities. Keep in mind that there are some limitations to subscriptions: You can create up to 100 subscriptions. Each subscription can include up to 10 sheets. A single subscription can have up to 100 recipients. Certain objects like filter panes, tab containers, and dynamic charts cannot be subscribed to. Once set up, you'll receive recurring emails with your preferred sheet or chart, allowing you to stay updated with the latest data at scheduled times. [https://help.qlik.com/en-US/cloud-services/Subsystems/Hub/Content/Sense_Hub/Reporting/Subscription-reports.htm]
- Q: How do I define my machine learning problem?
  A: To define your machine learning problem, follow a structured framework consisting of four key parts: Event trigger: Identify the action or event that initiates new predictions. Each trigger corresponds to a single row of data in your dataset. Target: Determine the specific outcome you want to predict. This could be a numerical value (for regression problems) or a categorical value (for classification problems). Features: Select the relevant attributes or variables that will be used to make predictions. These are the input columns in your dataset that influence the target outcome. Prediction point: Establish when the prediction needs to be made in relation to the event trigger. By carefully considering these elements, you can transform your business use case into a specific and actionable machine learning question. This approach helps avoid common pitfalls and sets the foundation for developing a good predictive model. Once you have defined your machine learning problem, the next steps involve: Preparing your training dataset by collecting high-quality, relevant data. Creating an automated machine learning experiment to train and evaluate your model. Remember that the quality of your input data significantly impacts the predictive output. A well-defined machine learning question and a properly structured dataset are crucial for successful machine learning experiments. [https://help.qlik.com/en-US/cloud-services/Subsystems/Hub/Content/Sense_Hub/AutoML/machine-learning-framework.htm] [https://help.qlik.com/en-US/cloud-services/Subsystems/Hub/Content/Sense_Hub/AutoML/machine-learning-basics.htm]
